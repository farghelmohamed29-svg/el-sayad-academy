# خطة تنفيذ EL SAYAD ACADEMY

هذه الخطة تخص المستودع الجديد فقط: `farghelmohamed29-svg/el-sayad-academy`.

## المطلوب النهائي
- جميع المراحل: ابتدائي (1–6)، إعدادي (1–3)، ثانوي (1–3).
- اختيار النظام الثانوي: الثانوية العامة أو البكالوريا المصرية، مع المسار عند انطباقه.
- يختار الطالب المرحلة والصف والنظام مرة واحدة عند إنشاء الحساب؛ التغيير اللاحق للإدارة فقط.
- حسابات منفصلة للطالب وولي الأمر والإدارة، بصلاحيات خادمية لا تعتمد على إخفاء عناصر الواجهة.
- صفحة طالب تعرض المواد المطابقة لصفه ونظامه وسنته الدراسية.
- لكل مادة: منهج، وحدات، دروس، شرح، فيديو، ملخص، امتحان درس/وحدة/شامل، ونتائج وتقدم.
- الدروس العملية تتضمن ملخصًا ومشهدًا ثلاثي الأبعاد مخصصًا للتجربة نفسها، مع دعم التدوير والتكبير.
- الاشتراكات والدفع لا تتفعّل إلا بعد مراجعة إدارية موثقة.

## قواعد اعتماد المناهج
لا تُدرج مادة على أنها «معتمدة من الوزارة» إلا بعد تسجيل رابط مصدر رسمي مباشر، والسنة الدراسية، والصف، والنظام، وتاريخ المراجعة. أي قائمة لم تراجع توضع بوضوح كبيانات تجريبية ولا تظهر للطلاب باعتبارها مقررات نهائية. البوابة الرسمية: https://moe.gov.eg/

## الحالة التي تم التحقق منها في المستودع
- الواجهة الحالية موجودة في `index.html` و`style.css` و`app.js`.
- `app.js` يحفظ اختيار الطالب في localStorage؛ هذا قفل تجريبي على المتصفح وليس حماية للحساب.
- `supabase-schema.sql` ملف تأسيسي يحتاج مراجعة وتطبيقًا واختبارًا على مشروع Supabase قبل الاعتماد.
- المجسم الحالي مكعب عام، وليس نموذجًا علميًا مخصصًا لكل تجربة.
- المواد والدروس الظاهرة عينات توضيحية وليست قائمة وزارية موثقة.
- لم يتم تنفيذ SQL على Supabase، ولم يتم ربط تسجيل الدخول أو الدفع، ولم يتم نشر إصدار إنتاجي جديد.

## ترتيب التنفيذ الآمن
1. تثبيت مخطط قاعدة البيانات ومراجعة الجداول الموجودة فعليًا في Supabase قبل أي migration.
2. تفعيل Supabase Auth وربط ملف الطالب بالمستخدم، وفرض قفل المرحلة/الصف من قاعدة البيانات مع صلاحية إدارية فقط.
3. إضافة صلاحيات منفصلة للطالب وولي الأمر والإدارة واختبار RLS بحسابات تجريبية.
4. بناء سجل المقررات بحسب السنة والصف والنظام وإدخال المواد بعد مطابقتها للمصادر الرسمية.
5. بناء إدارة الوحدات والدروس والوسائط والامتحانات، مع عدم إرسال مفاتيح الإجابات إلى المتصفح.
6. ربط نتائج الاختبارات والتقدم والاشتراكات ومراجعة الإيصالات.
7. إضافة نماذج 3D مرتبطة بكل درس عملي، لا مجسمًا عامًا موحدًا.
8. اختبار الهاتف وإمكانية الوصول والأمان والنسخ الاحتياطي، ثم طلب موافقة صريحة قبل دمج التغييرات في `main` أو نشرها.

## تنبيه أمان
لا تضع مفاتيح `service_role` أو كلمات مرور أو رموز وصول داخل ملفات الواجهة أو المستودع. مفاتيح Supabase العامة فقط يمكن استخدامها في المتصفح مع سياسات RLS صحيحة. لا تُرفع بيانات طلاب حقيقية أثناء التطوير.
